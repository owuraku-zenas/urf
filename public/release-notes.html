Universal Radiant Family (URF) June 2026 — System Update

What's New in the URF System

A summary of the latest improvements and fixes — written for all users.

Fix

Members List Now Shows Everyone

Previously, switching to a past semester (e.g. "First Semester 2024/25") would cause the Members page to only show the members who joined in that particular semester — hiding everyone else. This was confusing because the dashboard would show 32 members while the list showed only 8.

This has been fixed. The Members page now always shows every member regardless of which semester is selected. The semester selector still works normally on all other pages (events, attendance, reports).

New

All Users Can Now Switch Between Semesters

The semester dropdown in the top navigation was previously disabled for non-admin users — they were locked into only seeing the current active semester.

Now everyone can switch. Whether you are an admin or a regular user, you can click the semester selector and choose any past or current semester to view data from that period. Your selection is remembered even after you close and reopen the app.

New

You Can Now Add Data to Past Semesters

It was not previously possible to create events or record attendance for semesters that had already been closed. This made it impossible to backfill historical data.

Two improvements were made:

  • Event creation: When creating a new event, the form now includes a Semester dropdown. You can pick any semester — past or present — so events can be properly filed under the right period.
  • Attendance page: The event list on the Attendance page now filters based on whichever semester you have selected. Switch to an old semester and only its events appear, making it straightforward to fill in historical attendance records.

Note: There are no restrictions on the system side — any admin can write data to any semester at any time.

New

Archive Semesters for Long-Standing Members

Some members have been part of URF since 2018 or earlier — long before the system started recording semesters. When these members were added, the system incorrectly labelled them as "New Members" in the current semester, which was inaccurate.

How it works now:

  • An admin can create a special Archive Semester (e.g. covering 2015–2022) by ticking the "Archive semester" checkbox when creating or editing a semester.
  • When adding a member whose join date falls within that archive range, they are automatically given a LEGACY status instead of "New Member".
  • If a member's join date doesn't match any semester at all, they also receive LEGACY status automatically.
  • Legacy members appear with an amber LEGACY label in the Members list and are never penalised in commitment calculations — their historical attendance data simply isn't tracked.
Improvement

Academic Level Calculation Fixed & Expanded

The system that automatically calculates a member's academic level (100, 200, 300, 400 …) had two problems:

  • It stopped at Level 400 — anyone who had been a student for more than 4 years showed a blank level.
  • It assumed every university starts its academic year in August, which is not always true.

What changed:

  • Levels now go all the way up to 600 and then ALUMNI — no more blank levels for older members.
  • A new optional field — Academic Year Start Month — lets you record which month a member's university year begins (e.g. January, September). This defaults to August if left blank.
  • A new optional field — Programme Duration — lets you record how many years the member's course lasts (2, 3, 4, 5, or 6 years). The system uses this to know when the member should become an Alumnus. Defaults to 4 years.

Both fields appear on the Add Member and Edit Member forms and are completely optional.
